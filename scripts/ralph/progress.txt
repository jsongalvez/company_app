## Wed Jul 15 2026 - Feature: multi-token client search (AND semantics)
Thread: unavailable
- Root cause: Multi-word queries like "dolores vargas" or "dolores 0995300222" were treated as a single search pattern, never matching across multiple columns. Splitting into tokens and AND-ing them allows each token to independently match any column.
- Fix: Search now splits the query into whitespace-delimited tokens. Each token is independently matched against first_name, last_name, middle_name (ILIKE %token%), and phone_number (LIKE token%). All tokens must match for a row to be included (AND semantics).
- The token condition building happens inside the where {} block so `like` remains available via SqlExpressionBuilder receiver — no extra imports needed.
- Examples:
  - "dolores vargas" → token "dolores" matches first_name, token "vargas" matches middle_name → result found
  - "dolores 0995300222" → token "dolores" matches first_name, token "0995300222" matches phone → result found
  - "dolores" (single token) → behavior unchanged from before
- Files changed:
  - MODIFIED: backend/.../repository/ClientRepository.kt (tokenized search with AND semantics)
  - MODIFIED: scripts/ralph/progress.txt
- Quality: :backend:detekt :backend:ktlintCheck :backend:test :backend:jmhClasses (BUILD SUCCESSFUL).
