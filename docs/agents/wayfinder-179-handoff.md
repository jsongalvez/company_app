## Patterns + learnings

- **Verify the artifact, not the assumption — aarch64's wall is x86_64-only build tools, and it's per-tool.** The first build failure said only "AAPT2 Daemon startup failed". The real fact came from probing `dl.google.com` directly (HTTP 200 for `-linux`, 404 for `-linux-arm64`) and `file` on the extracted ELFs: AGP's aapt2, SDK build-tools' native tools, and platform-tools adb are all x86_64-only on Linux. cmdline-tools and the platform android.jar are arch-neutral — the SDK itself installs fine on aarch64; it's the native pieces that can't run. Same discipline as the #178 "facts-via-code": don't trust the blog post, probe the store.
- **`local.properties` beats `.bashrc` for daemon-launched shells.** The chain's spawned sessions inherit env from the tmux daemon, and non-interactive bash reads neither `.bashrc` nor `.profile`. `.bashrc` alone would have left the next pre-push broken. `sdk.dir` in the gitignored `local.properties` is AGP's first-class discovery mechanism and works regardless of env — verified by running the gate with both vars unset. (Keep `.bashrc` too: it serves interactive/admin shells and the wizard.)
- **Idempotency-first for wizard stages.** Each step of the SDK stage checks its own precondition (binfmt file exists, loader exists, sdkmanager executable, platform dir, `.bashrc` line, `local.properties` line) before acting, so a re-run is a no-op. Matches how the wizard's other stages guard on `if vps '...'` re-runs.
- **Quote-shaped to the transport.** The wizard's `vps '...'` wrapper cannot carry inner single quotes, so the remote commands use double-quoted `echo -e "\n..."` with `\$` escapes and an unquoted heredoc delimiter (no `$` in the body). The runbook (which the human pastes) can use the natural quoting instead. Two audiences, two forms, same content.
- **Prior-session patterns unchanged:** claim-first (n/a — no map ticket), facts-via-code, one-ticket-per-session, commit local not pushed, gate green before commit, harness/verify-before-commit.
