## Patterns + learnings (cumulative across sessions)

- **Session-51 additions**:
  - **The fix-that-didn't-land class is a mechanical-replacement hazard**: six occurrences in one build, every one from a python string-replace that silently failed to match (no assert, no verify). The counter: after EVERY batch fix, grep the actual file for the changed lines BEFORE committing — and tell the review phases to verify against files, never commits. The register entry should note "verify-by-grep after every automated replacement".
  - **The review phases' file-reading discipline pays off**: the two update actions' missing guards were caught FOUR times by phases reading the file while the commit claimed them fixed. When a phase reports a claim false, treat it as authoritative until grep-proven otherwise.
  - **Transport-failure tests need `advanceUntilIdle`, not `runCurrent`**: the ApiClient's `HttpRequestRetry` (maxRetries=3) schedules virtual-time delays that `runCurrent()` never elapses — the assertion ran before the retry chain completed.
  - **A locked-spec re-rate keeps the loop honest**: the rows/cards toggle sat as an accepted SOFT through three passes until P1 re-rated it HARD against the locked #105 D5 language ("toggle to full-day cards") — the resolution text, not the outline, is the lock.
- Prior-session patterns unchanged: claim first, build per module AGENTS.md, phased loop with `git diff <last-pass-commit>` per pass, batch-fix commits, exit at one full pass with zero HARD, resolution comment → close → map update → handoff. One ticket per session. The #153 handoff's "V19" migration claim was false — verify migration numbering against the actual files (`ls backend/src/main/resources/db/migration/`), never handoffs.
