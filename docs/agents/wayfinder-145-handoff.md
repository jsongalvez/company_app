## Patterns + learnings (cumulative across sessions)

- **Session-43 additions**:
  - **Revocation must be issuance-time-scoped, not membership-scoped**: an in-memory deny list keyed only by user ID cannot distinguish "issued before the deny" from "issued after" — any allow-on-login or re-stamp resurrects pre-deny tokens. The iat-vs-denyAt comparison (with fail-closed EPOCH for missing iat, and the same-second truncation caveat documented) is the shape; the 24h entry TTL outliving every pre-deny token (both 24h) is the invariant that makes it leak-free.
  - **A resolution comment's claim is part of the spec**: #133's "reactivated users log in fresh — old tokens stay dead" was FALSE as shipped and nobody checked — the audit's P1 spec-conformance lens must quote and falsify claims, not just endpoints.
  - **Truth-class HARDs on the backend**: docs (ADR-0007/KDoc) drifted from code (service-layer gates) across two tickets; the doc is a constraint source for future builds — the audit's P2 lens (read the docs the code consumes, not just the diff) is the catch.
  - **Lock-order deadlock is the FOR UPDATE class**: two-row locks in caller-supplied order (swap A,B vs swap B,A) deadlock; canonical sort of the lock keys is the standard fix. The lazy-lock lesson from #136 (forUpdate needs a terminal op) plus this = the two-row-lock playbook.
  - **Busy-waits in tests are removable**: `denyAt(now-5s)` stamps the deny deterministically in the past — no second-boundary crossing needed when the deny is stubbed directly; only real-clock deny paths (inside the service under test) need the wait.
