Patterns + post-cache validations (cumulative across sessions 7 + 8 + 9):
- **`viewModelScope.cancel()` extension** (new this session, applied in `NotificationBadgeViewModel.dispose()`): `kotlinx.coroutines.cancel` extension on `CoroutineScope` cancels the underlying Job of the scope. `viewModelScope` is provided by `androidx.lifecycle.ViewModel`'s `viewModelScope` extension which internally delegates to a `SupervisorJob`; calling `coroutineScope.cancel()` cancels this supervisor + propagates the cancellation to all child coroutines launched via `viewModelScope.launch` (handler.launch's launched coroutines are children of the supervisor). After `dispose()` is called, subsequent `viewModelScope.launch` calls would throw `IllegalStateException (Job was cancelled)`, but our consumer (the `DisposableEffect` onDispose clause at composable-subtree-leave) is one-shot — no subsequent launches expected. The pattern is the canonical Compose Multiplatform equivalent of ViewModelStoreOwner-driven `onCleared()` cancellation, applicable to any future `: ViewModel()` extension that needs explicit lifecycle-binding outside the standard Android `viewModel()` factory + `ViewModelStoreOwner` machinery (Compose Multiplatform on desktop lacks a ready-made `LocalViewModelStoreOwner` setup → `viewModel()` factory alternatives require custom wiring).
- **`if (isPostClockIn) { remember { VM(...) }; DisposableEffect(vm) { onDispose { vm.dispose() } } }` gated pattern** (new this session, the shell-scope mechanism for poller VMs): Compose runtime correctly evicts the `remember` and `DisposableEffect` slots when the `if`-block's branch evaluates to false (the slot-table keys are call-site-position-keyed), so the `DisposableEffect.onDispose` fires whenever the gated subtree leaves composition (when `isPostClockIn` flips true → false). Honors #96 Q6 literal "dies on clock-out / login expiry" requirement within ADR-0020 stable-composition invariant. Pattern is ad-hoc for now (single lifecycled poller VM); future long-running shell-scoped coroutines can lift it verbatim from `NotificationBadgeHost`.
- **`filterIsInstance<UiState.Success<Int>>().collect { ... }` collector pattern** (new this session, in `NotificationBadgeViewModel`): standard ktlint-friendly way to react to Success transitions only, dropping Loading/Error/Idle — preserves "last successful refresh, never last attempt" semantics (#97-Q5 mirror) without explicit state-pattern matching in the collector body. Used as the badge count pipe from `_pollResult` (handler's scratch state flow) to `NotificationState` (singleton authoritative state for render sites).
- **`transform = { val body = ...; NotificationState.decrementUnread(); body }` side-effect-in-transform for success-only-on-2xx** (new this session, in `NotificationViewModel.markRead`): exploits `ApiCallHandler.launch`'s contract that `transform` is invoked only inside the `if (response.status.isSuccess())` branch — so the optimistic decrement is gated on successful HTTP-2xx PATCH. Bounded at 0 via `NotificationState.decrementUnread`'s `max(0, current - 1)`. Alternative pattern would have been a collector on `_markReadResult.filterIsInstance<UiState.Success<NotificationResponse>>().collect { NotificationState.decrementUnread() }` — equivalent semantics with `StateFlow` distinctUntilChanged drop-protection; transform-side chosen for directness + the body variable's already-being-parsed-locally + avoidance of an extra nested collector that could subtly skip repeat-success emissions if the user happens to markRead the same notification twice (the second PATCH returns identical body → distinctUntilChanged drops the second Success → no second decrement; the transform-side path fires on EVERY successful PATCH regardless of identity).
- **ktlint `backing-property-naming` rule** (new this session — first time enforced): private vars with leading underscore (`_xxx`) are flagged if no matching public property without underscore exists. `composeApp/src/.../viewmodel/NotificationBadgeViewModel.kt` first-pass draft had `_pollResult` only — ktlintFormat failed with "Backing property is only allowed when a matching property or function exists (cannot be auto-corrected)" at line 20. Fix: pair `private val _pollResult = MutableStateFlow<UiState<Int>>(UiState.Idle)` with `val pollResult: StateFlow<UiState<Int>> = _pollResult.asStateFlow()` (mirrors the codebase-wide `_xxx` + `xxx asStateFlow()` convention from `DrawerViewModel`/`SessionState`/`NotificationViewModel`). Alternative option (drop underscore and rename to `pollResult` private solo) was avoided — preserved convention rather than refactoring differently the codebase's `_xxx`+`xxx` pair rule.
- **ktlint "no comment between args" rule** (carried from session-8): design-rationale comments placed INSIDE a composable call's args list are auto-correctable-to-fail; placement ABOVE the call statement preserves the "future-dev sees the rationale next to the override" intent. Session-9 only added the mandated 3-line inline comment at `NotificationBadgeViewModel.kt:34-36` (placed inside a `.collect { state -> ... }` lambda body BEFORE the `NotificationState.setUnreadCount(state.data)` statement — not between args; passes ktlintFormat verbatim).
- **detekt `UnusedPrivateProperty` rule applies to class-scope members; function-local unused vals are not flagged** (verified this session): the local `val count = unreadCount` alias in `DrawerContent.kt:89` and the local `val unreadCount: Int? by NotificationState.unreadCount.collectAsState()` in `AppNavHost.android.kt` were both referenced downstream (smart-cast ternary or named-arg value), confirmed safe via `:composeApp:detektMetadataCommonMain` — zero new violations introduced; baseline reduced by 0:1 (was 58, still 53 — the previous #107 session reduced InkSubtle to public; my new files have no `_xxx` underscore violations since `_pollResult` is paired; `60_000L` extracted to `private companion object REFRESH_INTERVAL_MS = 60_000L` to dodge `MagicNumber`).
- **`kotlinx.coroutines.cancel` extension import resolved at `import kotlinx.coroutines.cancel`** (new this session): the extension function `CoroutineScope.cancel(cause: Exception? = null)` lives in `kotlinx.coroutines` package; explicit import needed for cross-namespace visibility. Verified multiplatform-compatible (multiplatform `kotlinx-coroutines-core`; `Main` dispatcher set up by `androidx.lifecycle.viewmodel`).
- **`onDispose` is a `DisposableEffectScope` member function — NOT a top-level importable function** (new this session, learned via hard way): first-pass attempt to import `androidx.compose.runtime.onDispose` together with `androidx.compose.runtime.DisposableEffect` failed compile with "Unresolved reference 'onDispose'" — `onDispose { ... }` inside a `DisposableEffect(key) { ... }` block resolves via the lambda's `DisposableEffectScope` receiver (member function on the interface). No import needed. Future sessions adding `DisposableEffect` blocks should drop the `onDispose` import; the receiver member call works automatically.
